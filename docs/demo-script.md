# 3분 데모 대본

준비: `npm run db:seed`, `npm run dev`, 브라우저에서 http://localhost:5173 열기.

## 0:00 문제 (20초)

"AI 에이전트에게 지급 권한을 주면 프롬프트 인젝션 한 번이 금융 사고가 됩니다. 도장은 AI를 믿게 만드는 대신, 믿지 않아도 안전하게 설계했습니다."

## 0:20 정상 결재 (60초)

1. 김사원으로 `가람상사 청구서 A-2026-1101 300만 원 지급해 줘`를 보냅니다.
2. Claude가 ERP를 조회하고 처리안을 올린 뒤 멈추는 장면을 보여 줍니다.
3. 오른쪽 품의서에서 전결 한도 초과 사유와 결재란을 가리킵니다.

"결재선은 Claude가 아니라 전결 규정 코드가 계산합니다."

## 1:20 재시작 (30초)

1. `npm run dev` 터미널에서 `Ctrl + C`로 서버를 끕니다.
2. 다시 `npm run dev`로 실행합니다.
3. 박팀장으로 결재함을 열고 **승인**합니다. 도장이 찍히는 장면을 보여 줍니다.
4. 김사원으로 돌아와 지급 완료를 확인합니다.

"대기 상태가 PostgreSQL에 있어 서버가 재시작돼도 멈춘 지점부터 이어집니다."

## 1:50 공격 (50초)

1. `npm run db:seed`로 초기화하고 김사원의 **새 대화**를 시작합니다.
2. **숨은 지시가 든 청구서 PDF로 요청**을 눌러 보냅니다.
3. PDF 뷰어로 `invoice-attack.pdf`를 열어 사람 눈에는 정상 청구서로 보인다는 점을 보여 줍니다.
4. 품의서의 입금 계좌가 공격자 계좌가 아니라 원장 계좌이고, 결재가 필요하다는 점을 보여 줍니다.

"모델이 설령 속아도 지급 도구가 없고, 계좌는 서버가 원장에서 가져옵니다. 테스트에서는 완전히 조종당한 모델도 재현해 지급 0건을 확인합니다."

## 2:40 마무리 (20초)

평가 결과와 ADR을 보여 줍니다.

"15년간 쌓은 권한, 트랜잭션, 멱등성, 감사의 경험을 AI 에이전트에 그대로 적용했습니다."
