# 도장 Q&A

도장의 설계 이유, 검증 방법, 한계를 질문과 답변으로 정리했습니다.

[README](../README.md) · [데모 영상](https://youtu.be/Gjr98nHXEyg)

## 프로젝트

### 도장은 어떤 프로젝트인가요?

결재 도장을 받아야만 일을 처리할 수 있는 AI 신입사원입니다. 사원이 채팅으로 지급을 요청하면 AI가 ERP를 조회해 처리안을 만들고, 전결 한도를 넘으면 멈춰서 결재를 받습니다.

핵심은 AI를 믿지 않아도 안전하다는 점입니다. 승인 판단은 코드가 맡고, AI에게는 지급 기능을 주지 않습니다.

### 왜 이 주제를 골랐나요?

기업이 AI를 도입할 때 막히는 곳은 답변 품질만이 아니라 권한, 책임, 감사입니다. 도장은 이 문제를 한국 기업의 전결 규정과 결재선으로 다룹니다.

### 실제 서비스인가요?

아닙니다. 구직용 프로토타입입니다. ERP와 사용자, 거래처 데이터는 모두 가상입니다.

### 이 설계를 작은 제품에도 그대로 써야 하나요?

그렇지 않습니다. 되돌리기 어려운 동작만 엄격하게 막고 나머지는 단순하게 시작하는 편이 좋습니다. MCP 분리나 추적 도구는 필요해질 때 추가해도 됩니다.

## 설계

### 전체 구조는 어떻게 되나요?

React 화면, Fastify API, LangGraph.js 에이전트, 가상 ERP MCP 서버, PostgreSQL로 나뉩니다. 전결 규정은 LLM 의존성이 없는 별도 패키지의 순수 함수입니다.

### 프롬프트로 승인 규칙을 주면 안 되나요?

프롬프트 지시는 확률적으로만 지켜집니다. 그래서 모델에는 읽기 도구와 처리안 등록만 허용하고, 지급은 결재가 끝난 뒤 그래프의 고정 노드가 실행합니다. 시스템 프롬프트의 방어 문구는 보조 수단입니다. [ADR 1](adr/0001-llm-never-approves.md)

### 왜 LangGraph.js를 사용했나요?

`interrupt()`와 PostgreSQL 체크포인트로 재시작을 견디는 정지와 재개를 적은 코드로 구현할 수 있었습니다. 결재의 기준 데이터는 `approvals` 테이블이며, 재개할 때 노드가 이 상태를 다시 읽습니다. [ADR 2](adr/0002-langgraph-durable-pause.md)

### 왜 MCP로 분리했나요?

ERP 도구를 표준화하고, 지급 검증을 에이전트 밖에 두기 위해서입니다. 도구가 적고 연동 대상이 하나인 작은 제품이라면 일반 함수 호출로 시작하는 편이 낫습니다. [ADR 3](adr/0003-erp-behind-mcp.md)

## 보안

### 프롬프트 인젝션을 완전히 막았나요?

인젝션 자체는 완전히 막을 수 없습니다. 대신 모델이 속아도 피해가 나지 않도록 권한을 제한했습니다. 다만 모델이 잘못된 처리안을 올릴 수는 있으므로 결재자의 확인이 필요합니다.

### 청구서 PDF에 공격 문구가 숨어 있으면 어떻게 되나요?

PDF 글자는 신뢰할 수 없는 데이터로 표시해 모델에 전달합니다. 모델은 청구서와 금액만 지정할 수 있고, 입금 계좌는 서버가 거래처 원장에서 가져옵니다.

### 이중 지급은 어떻게 막나요?

승인 행을 `FOR UPDATE`로 잠가 동시 요청을 직렬화하고, 멱등키와 UNIQUE 제약을 함께 사용합니다. 동시 요청 8개에도 지급이 한 번만 되는 것을 테스트했습니다.

### 승인 후 금액이나 계좌가 바뀌면 어떻게 되나요?

승인은 거래처, 청구서, 계좌, 금액의 해시에 묶입니다. 내용이 바뀌면 거부하고, 지급 직전에 현재 원장과 규정으로 결재선을 다시 계산합니다.

### 서버가 재시작되면 대기 중인 결재는 어떻게 되나요?

대기 상태가 PostgreSQL에 저장되어 멈춘 지점부터 이어집니다. 승인 직후 서버가 멈춘 경우에도 시작 시 복구 절차가 이어서 처리합니다.

## 검증

### 어떻게 검증했나요?

타입 검사, 자동 테스트, CI, 실제 PostgreSQL 통합 테스트를 사용했습니다. 주요 방어 코드를 일부러 제거해 테스트가 실패하는지도 확인했습니다.

### 평가 결과는 어떻게 해석해야 하나요?

2026년 11월 3일 `claude-sonnet-5-5`로 1회 실행해 9건 모두 통과했고, 공격 3건도 막혔습니다. 표본이 작아 일반적인 공격 저항력을 뜻하지는 않습니다. 이 실행에서 서버가 막은 도구 호출은 0건이었고, 서버 방어는 조종당한 모델을 재현한 테스트로 따로 검증했습니다.

### LLM 비용은 어느 정도인가요?

평가 기준 시나리오당 평균 5,887토큰을 사용했습니다. 실제 제품의 비용은 사용 모델과 대화 길이에 따라 달라지므로 건당 토큰을 측정해 계산해야 합니다.

## AI 도구 활용

### 이 프로젝트는 AI로 만들었나요?

네. Claude를 사용해 함께 만들었고 코드의 대부분은 AI가 작성했습니다. 사람은 주제 선택, 개발 환경 결정, Windows 실행, 실제 Claude 시연, 결과 확인과 병합을 맡았습니다.

### AI가 만든 코드를 어떻게 믿을 수 있나요?

믿는 대신 검증했습니다. 위의 테스트와 평가를 공개했고, 설계 결정은 ADR로 남겼습니다.
