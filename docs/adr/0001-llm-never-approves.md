# ADR 1: LLM은 승인하지 않는다

## 상황

에이전트가 돈을 움직이는 도구를 호출할 수 있으면, 프롬프트 인젝션 한 번이 곧 사고가 됩니다. 프롬프트로 "승인 없이 실행하지 말라"고 지시해도 그 지시는 확률적으로만 지켜집니다.

## 결정

LLM의 판단을 보안 경계로 쓰지 않습니다.

- 모델에는 읽기 도구와 `propose_payment`만 제공합니다.
- 결재선은 LLM 의존성이 없는 `packages/policy`의 순수 함수가 계산합니다.
- 지급은 결재가 끝난 뒤 그래프의 고정 노드가 실행합니다.
- `execute_payment`는 호출자를 믿지 않고 승인, 해시, 결재선, 잔액을 다시 검증합니다.

## 결과

모델이 완전히 조종당해도 할 수 있는 일은 처리안 등록까지입니다. 시스템 프롬프트의 방어 문구는 사용자 경험을 위한 보조 수단이고, 보안 보장은 코드에 있습니다.

대신 모델이 대화 중 지급을 직접 끝낼 수 없어 흐름이 고정됩니다. 업무 자동화의 유연성보다 사고 방지를 우선한 선택입니다.

## 검증

`apps/api/test/hardening.test.ts`는 숨은 지시에 넘어간 모델을 재현합니다. 모델이 지급 도구를 지어내고 공격자 계좌를 넘겨도 지급은 0건이고, 결재 문서의 계좌는 거래처 원장의 값입니다.
