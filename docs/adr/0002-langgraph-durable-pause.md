# ADR 2: 결재 대기에 LangGraph.js를 사용한다

## 상황

결재는 몇 시간이 걸릴 수 있고 그사이 서버가 재시작될 수 있습니다. 대기 상태를 메모리에 두면 승인된 업무가 사라지고, 직접 상태 머신을 만들면 대화 기록과 실행 위치를 함께 관리해야 합니다.

## 결정

LangGraph.js의 `interrupt()`로 실행을 멈추고, PostgreSQL 체크포인트에 상태를 저장합니다.

- 결재의 정답은 `approvals` 테이블에 둡니다. 재개 신호는 깨우는 역할만 하고, 노드는 결재 상태를 다시 읽습니다.
- `interrupt()`로 재개하면 노드가 처음부터 다시 실행되므로, 부수 효과는 별도 노드로 분리합니다.
- 처리안은 대화와 도구 호출 ID로, 지급은 결재 ID로 멱등성을 보장합니다.
- 서버 시작 시 `recover()`가 끝난 결재를 찾아 재개합니다. 승인 커밋과 재개 사이에 서버가 멈춰도 업무가 이어집니다.

## 결과

재시작을 견디는 실행을 적은 코드로 얻었습니다. 대신 LangGraph의 재실행 의미를 이해해야 하며, 체크포인트에 비밀이 남지 않도록 주의해야 합니다.

그래서 토큰은 상태나 설정에 넣지 않습니다. 필요한 순간에 60초짜리 토큰을 발급하며, 테스트로 체크포인트에 JWT가 없음을 확인합니다.
